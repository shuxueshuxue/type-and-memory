# 能量机制：旧版逐条对照

旧版出处：`frontend/src/engine/EditorEngine.ts`、`hooks/useInspiration.ts`、`App.tsx`（能量条）、`backend/stateless_analyzer.py`。
新版出处：`src/core/pace.ts`、`src/core/text.ts`、`src/editor/mount.ts`、`src/agents/llm.ts`。

| | 旧版 | 新版 | 出入和理由 |
|---|---|---|---|
| 文字的重量 | 句末符号和换行 4，汉字和假名 2，中文逗号 0，其余 1 | 相同 | 无 |
| 怎么积累 | 每次改动算全文重量，只把增加的部分记进能量；删字不退 | 相同（按每次输入的净增量记） | 无 |
| 一条批注的价钱 | 50 | 50（`pace.cost`） | 无 |
| 什么时候去要批注 | 每写完一个分句（`. ! ? 。 ！ ？ ，` 和换行）就要一条；同时只有一个请求在途；一条批注显示之后立刻再要下一条 | 网页、Obsidian：相同。咕咕、DeepSeek Harness：每攒够 50 能量才要一次，一次最多要 3 条 | 在这两个宿主里，「要一次」是 agent 完整的一轮（十几秒、几万 token，还会在聊天里留一条消息），照旧版每个逗号要一次不现实。显示的节奏不变，见下一行 |
| 什么时候显示 | 要来的批注先放进等待队列；没花掉的能量够 50 就取一条显示，扣 50；后到的先显示 | 相同（`held` 就是等待队列） | 无。所以批注是在能量条走满的那一刻出现，不是等模型返回 |
| 冷却 | 没有单独的冷却，节奏只由能量决定 | 相同 | 无 |
| 等待队列里已有批注时 | 新分句仍会再去要 | 不再要，等这条显示了再要 | 少浪费一次调用；显示节奏不受影响 |
| 批注失效 | 文本不再以当时的快照开头就丢弃；短语找不到、和已有批注重叠，各记一份黑名单发回后端，再重新要 | 留批注的那一刻就校验：找不到或重叠当场拒绝，把原因告诉 agent 让它换一句。显示之后短语被删，批注隐藏，短语回来它也回来 | 批注钉的是原话，不需要快照和黑名单；撤销删除能把批注带回来 |
| 各个声音怎么分 | 模型从启用的声音里自己挑一个，没有配额 | 网页、Obsidian：相同（五个内省声音）。咕咕、DeepSeek Harness：声音就是 agent 本人，它可以用 `as` 扮演角色 | owner 的要求：聊天里的 agent 充当原来的 agent |
| 停顿时的轻声提示 | 停 2 秒且已有 10 个字以上，随机一个声音给一句「接下来写什么」；请求期间文本没变才显示；一打字就消失；不花能量 | 网页、Obsidian：相同（`pace.lull`）。咕咕、DeepSeek Harness：关闭 | 同上，每次停顿都是 agent 的一轮 |
| 界面上怎么显示 | 底栏：Weight、Applied、Groups 三个数字，加一根能量条（余数 ÷ 50），每攒满一格闪一下满格；设置里可以关 | 一根能量条，进度和闪动相同；`energyBar: false` 可以关 | 三个数字是调试信息，没有保留 |
| 刷新之后 | 能量历史随文档一起存，刷新后接着算 | 不存能量历史。打开时：已花 = 已显示的批注数 × 50，已赚 = 全文重量和已花里较大的那个 | 存储格式只有正文和批注，任何宿主都存得下。代价：靠删改赚到的能量刷新后不算 |
| 清空 | 文本清空，批注和能量一起重置 | 相同 | 无 |

## 只打字就有交互：四个宿主

| 宿主 | 写作者要做的 | 实测 |
|---|---|---|
| 网页（带后端） | 只打字 | `scripts/flow.mjs`：从第一个字到最后一个字没有任何点击，5 条批注在 8、13、18、23、27 秒出现，停顿后来了一句轻声提示 |
| 网页（纯前端） | 第一次在齿轮里填模型地址和 key，之后只打字 | 一次性设置，对应旧版的注册登录 |
| 咕咕 | 只打字。纸自己给聊天里的 agent 发悄悄话；群里有几个 agent 时默认第一个，不需要选 | 私聊里实测：打字 → 自动发出悄悄话 → 5 条批注；回话后 agent 在同一条批注下作答 |
| Obsidian | 第一次在设置里填模型地址；用命令把笔记开成这张纸；之后只打字 | 11-13 上午实测是只打字；能量机制改动之后没有重跑 |
| DeepSeek Harness | 只打字 | 实测：打字 → 会话里自动多一条消息 → agent 留了 3 条批注。用户不需要做任何事，但会话里看得到这些消息和 agent 的回合 |
